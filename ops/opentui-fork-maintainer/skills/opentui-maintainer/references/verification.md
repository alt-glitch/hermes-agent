# Owned processes and visible proof

Resolve binary, source checkout and engine before launching. An installed wrapper
may select an explicitly trusted worktree based on cwd. Candidate tests must select candidate source
explicitly with the existing source-root/Python overrides or candidate launcher.
An already-running global TUI cannot prove a candidate passed.

Create maintainer-owned herdr/termctrl sessions only. Never attach to, steer or
kill a user's agent. Inside herdr discover the current pane, then follow installed
`herdr --skill`. Version 0.8.2 `agent start` uses an explicit pane; create a sibling
first rather than assuming it splits. `agent prompt` submits the message.

Use termctrl `wait`, typed `send`, then `show` for visible assertions. Logs are
not alternate-screen state. Final runtime proof owns its own candidate session
and requires `/help` -> `Available Commands` plus the Hermes header; additional
feature assertions follow that baseline.

Capture before/after at matching dimensions and states, with source SHAs and
interaction recorded. Keep credentials and private conversations out. Missing
before evidence means after-only Preview, not a fictional recreation. Load
`before-and-after`, use its formatter, and upload with
`/home/daimon/.local/bin/gh` (2.100.0 supports `--attach`). `/usr/bin/gh` is older
and lacks it. Verify remote attachment URLs and the rendered PR; local paths
aren't public attachments. Preserve unrelated PR prose.

Run control-plane Python with `uv run --no-project --python <interpreter>`.
For canonical tests use explicit `/usr/bin/env` and command-local PATH with
pinned Node first, then `/usr/bin:/bin`, then required user tools. This host's
user `env` wrapper can exit zero without executing a test. Put the same command
boundary in external worker packets; require executed counts, not collection,
help or exit status alone. Inspect `scripts/run_tests.sh`: worktrees without a
local test venv accept `HERMES_PYTHON`, not `HERMES_TEST_PYTHON`.

Use managed `state/worktrees/sync-*` detached trees and full `git rev-parse HEAD`
SHAs for publication. Run the full maintainer suite on the integrated candidate
for runtime corrections: an offline-base pass does not cover new scheduler
contracts. Preserve provider/wire assertions when migrating a fixture seam.
Run unrelated Python files in fresh processes to avoid leaked import mocks.
Reproduce baseline failures in a clean worktree, never by stashing user work.

For fake subprocess pipes consumed by real kernel readers, use byte streams
with genuine `read1()` EOF, not unconstrained mocks. Register teardown before
execution so assertion failures release resources too. Keep environment
composition assertions; verify warning-clean repeats and the full owning file
before attributing a historical timeout to a fixture.

For GitHub targeted-rerun proof, compare execution-step timestamps/results and
completion times, not database IDs: GitHub can copy unchanged results into new
IDs. Preserve unrelated failure/cancellation conclusions and distinguish helper
submission from successful CI. Retained evidence:
`20260909T195913Z-90d8549d/capability-preservation.md`,
`20260909T222005Z-9ea2d31b/parent-tests.json`, and
`20260909T234515Z-917bc5d7/live-targeted.verdict.json`.

The candidate-bound passing runtime manifest authorizes publication. Inline tests
and screenshots don't replace it. Stop disposable owned sessions; retain only an
explicitly requested maintainer control session with its identity documented.
